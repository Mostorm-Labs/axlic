# AxLicense

AxLicense is a Windows C++20 command-line client that implements the **local licensing library plane**: one machine-wide Windows DeviceIdentity backed by a non-exportable persisted CNG P-256 key (TPM-first), offline verification and atomic installation of platform-signed credentials with anti-rollback, a local registration association, and a trust keyring. The client itself contains **no network code** and does not require a server: credential delivery, channel transport, RPC orchestration and receipt reporting belong to the consuming host (launcher bridge), which drives axlic exclusively through the `axlic.exe` CLI contract.

## Build and test

The frozen A0 toolchain is CMake 4.4.2, Visual Studio 2022 17.14 / MSVC 14.44, and Windows SDK 10.0.26100.0.

```powershell
cmake -S . -B build -G "Visual Studio 17 2022" -A x64 -T v143
cmake --build build --config Release
ctest --test-dir build -C Release --output-on-failure
```

The public commands currently implemented are:

```text
axlic status
axlic entitlement <entitlement_id>
axlic identity
axlic device-register
axlic device-register adopt <axldev_reference>
axlic device-register reset
axlic install <artifact_path> --policy-version <n>
axlic held-version
```

`axlic identity` must be run with machine-state write authority for first establishment. It returns only the public scheme, epoch, and 64-byte P-256 public identity as lowercase hex; provider key names and private material are never part of the CLI contract.

`axlic device-register` reports the dual-state self-report value for the connection identity: the 128-hex `identity_value` while unregistered (or after the local reference was dropped), or the platform-assigned `axldev_` reference once `adopt` has persisted it. `install` runs the frozen pipeline — A0 signature verification, payload device-reference match, `(authority_revision, credential_generation)` lexicographic high-watermark anti-rollback with idempotent same-version reinstall, and an atomic local commit; an empty-entitlements revocation credential is a legal install object. `held-version` returns the held `(authorityRevision, credentialGeneration, policyVersion)` triple (or the no-credential state) for version probes and reconciliation. Channel-transient values such as delivery references never enter axlic.

## Trust keyring

Verification trusts a merged key set: an **embedded production floor** compiled into the binary at build time from `client/keyring/trust-floor.json`, plus a state-root append overlay (`trust-keyring.v1.json`) where an entry with the same `key_id` overrides the floor entry (key rotation replacement). The merged set starts empty: an empty keyring is fail-closed, so nothing verifies until production public keys are embedded. The floor artifact is produced at packaging time by `tools/fetch_trust_floor.py`, which exports P-256 public keys from the signing backend (OpenBao transit; `VAULT_ADDR`/`VAULT_TOKEN` plus `--key` names) and never overwrites the existing artifact on failure. That tool is operator packaging tooling only — it is never part of `axlic.exe`, and the binary keeps zero network dependencies (enforced by the offline-boundary import scan).

The checked-in `reference/vectors/a0` corpus and `AXLIC_A0_FIXTURE_STATE` remain explicit test-only A0 regression adapters. Production `axlic.exe` does not read that environment variable. The A2 installation vectors live in `reference/vectors/a2/install.json` and are generated by `reference/tools/a2_reference.py` on top of the same independent reference signer.
